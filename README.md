# osnit-il — מנוע OSINT ציבורי מתמשך

מנוע שמתחיל ממאגר קיים, ממשיך לגלות מידע חדש מ**מקורות ציבוריים** באופן אוטונומי, ומרכז הכול לתמונה אחת שמתעדכנת — עם הוכחות ורמת ביטחון לכל נתון. (Python 3.10+, ללא תלויות חובה; `pypdf` אופציונלי ל־PDF.)

```
חיפוש → תוצאה ראשונית מיידית (מהמאגר) → גילוי מקורות → סריקה → פרסור → קורלציה → עדכון התמונה → סבב נוסף
```

## הפעלה מהירה

```bash
pip install pypdf                      # אופציונלי: תמיכה ב-PDF
python -m osnit serve --seeds seeds/example_seeds.txt   # UI + API + סריקה 24/7 על http://127.0.0.1:8080
python -m osnit search "יונתן חייט" --wait 600          # חיפוש עמוק מהטרמינל, תמונה מעודכנת אחרי 10 דקות
python -m osnit import ./archive --base-url https://example.org/files   # קבצים היסטוריים / JSONL
python -m osnit import-db old_tool.db --dry-run         # אילו עמודות זוהו בכל טבלה
python -m osnit import-db old_tool.db --label old-tool --delete-raw   # ייבוא מסד מתוכנה קודמת ומחיקת הקובץ
python -m osnit search "יונתן חייט מספר טלפון"           # שאילתה חופשית: שם + כוונה (טלפון / מייל / pdf / קורות חיים)
python -m osnit stats
python -m osnit forget "yonatan.hayat@alpha.co.il"   # בקשת הסרה
python -m unittest discover -s tests -t .               # בדיקות (ללא רשת)
python -m osnit eval tests/corpus_holdout               # מדידת איכות חילוץ על קורפוס מתויג
```

### מקורות גילוי (`--providers` / `OSNIT_PROVIDERS`)

| ספק | מה הוא נותן | הגדרה |
|---|---|---|
| `google` | חיפוש כמו בגוגל, כולל `"שם" filetype:pdf`, `site:` — דרך Google Programmable Search JSON API הרשמי | `GOOGLE_API_KEY` + `GOOGLE_CSE_ID` (מנוע שמוגדר לחפש בכל הרשת) |
| `serpapi` | תוצאות google.com דרך שירות API בתשלום | `SERPAPI_KEY` |
| `brave` | Brave Search API | `BRAVE_API_KEY` |
| `searxng` | מטא-חיפוש בהתקנה עצמית (מתאים ל-NAS) | `SEARXNG_URL` |
| `wikipedia` | חיפוש בוויקיפדיה עברית+אנגלית (ברירת מחדל) | — |
| `archive` | Wayback Machine: צילומים היסטוריים של אתרים שקשורים לנושא — מסמכים קודם (ברירת מחדל) | — |
| `ddg` | scraping של DuckDuckGo — opt-in בלבד | — |

ספק עם מפתח מופעל אוטומטית. לכל ספק בתשלום/מוגבל יש מכסה יומית (`OSNIT_BUDGET_GOOGLE=100` וכו'); משימות מעבר למכסה ממתינות ליום הבא.
גוגל עצמו לא נסרק ישירות (חוסם ואסור בתנאי השימוש) — רק דרך API.
כשאתר מזכיר את הנושא, נסרקים גם ה־sitemap שלו (מסמכים קודם) והצילומים ההיסטוריים שלו.

## מה בנוי

| יכולת | מימוש |
|---|---|
| סריקה רציפה | תור מקורות ב־SQLite, N workers, עדיפות (תוצאות חיפוש > קישורים מדף עם ממצא > crawl כללי), fairness לפי דומיין |
| נימוס | robots.txt (+Crawl-delay), השהיה לכל host, תקרת גודל/זמן, `Retry-After`, חסימת כתובות פנימיות (SSRF) גם בהפניות |
| פרסור | HTML (כולל JSON-LD, mailto/tel), PDF (כולל תיקון עברית הפוכה), DOCX, XLSX, CSV, JSON, TXT, VCF, XML/sitemap; קידודים windows-1255 / iso-8859-8 |
| חילוץ | שמות (התאמת נושא + תארים + צמידות תפקיד), ארגונים, תפקידים, מיילים (גם `[at]`/`[dot]`), טלפונים (נרמול ל־E.164), דומיינים, URLs, וקשרים ביניהם |
| נרמול/איחוד | ניקוד, אותיות סופיות, סדר שמות, גרשיים; תעתיק עברית↔לטינית (מילון + כללים, ניתן להרחבה ב־`data/name_variants.json`); איחוד שגיאות כתיב בטוח (עריכה ≤1, מילים ≥5 תווים) |
| איחוד בין שפות | ארגון/תפקיד/אדם בעברית ובאנגלית מאוחדים בתצוגה לפריט אחד (עם "גם: …"): שלד עיצורים + מילון שמות + דומיין משותף; מנכ"ל=CEO, יו"ר=Chairman וכו' |
| Evidence | לכל נתון וקשר: מקור, קישור, ציטוט, ביטחון, `first_seen` / `last_seen` |
| ביטחון | noisy-or על **דומיינים בלתי־תלויים** (עשר הופעות באותו אתר ≠ אישוש) |
| בלי עבודה חוזרת | hash של ה־raw ושל הטקסט, ETag / Last-Modified (304), מרווח סריקה שמוכפל כשאין שינוי |
| זיהוי שינויים | `source_changes` (כמה עובדות נוספו / נעלמו), ולכל ממצא סטטוס: **פעיל** / **נעלם מהמקור** / **היסטורי** (מיובא); התראת "נעלם" כשעובדה על הנושא ירדה מדף; ניסוח שהשתנה סביב אותה עובדה לא נחשב היעלמות |
| מה חדש מאז | `GET /api/subjects/<id>?since=<ts>` מסמן ממצאים חדשים ומסכם כמה נוספו/נעלמו; ה־UI זוכר מתי צפיתם לאחרונה בכל נושא |
| raw לא נשמר | ה־body נשאר בזיכרון בלבד ונזרק אחרי הפרסור; בסכמה אין עמודה לתוכן גולמי. בייבוא קבצים/מסדים: `--delete-raw` (או `OSNIT_DELETE_IMPORTED=1` כברירת מחדל) מוחק את הקובץ רק אחרי ייבוא מוצלח |
| הבנת שאילתה | "יונתן חייט pdf" / "נקודה PDF" / "filetype:docx" / "מספר טלפון" / "מייל" / "קורות חיים" → נושא + כוונה; החיפושים המבוקשים מתוכננים ראשונים, והתוצאה כוללת "תשובה לבקשה" |
| שער סבירות | דף ספריה (הרבה טלפונים) → רק שיוך באותה שורה, ביטחון ≤50%; דף ספאם → לא נשלף ממנו כלום; מספר מרכזייה שמשויך ל־3+ אנשים → לא אישי; `info@`/`office@` → שיוך חלש; מספרים רצופים/חוזרים ו־`example.com` → נדחים |
| ייבוא מסד קיים | `import-db`: SQLite / CSV / TSV / JSON / JSONL, זיהוי עמודות בעברית/אנגלית או קובץ מיפוי, תאריך הגילוי ההיסטורי נשמר לכל רשומה, עמודות טקסט/HTML עוברות חילוץ מלא, כתובת המקור נכנסת לתור לאימות מחדש |
| חיפוש עמוק | וריאציות שם → תוצאה מיידית מהמאגר (כולל איחוד עם אזכורים קודמים) → משימות גילוי → סבבי הרחבה אוטומטיים (ארגון, מייל, דומיין שנמצאו) עד `--hours` |
| מופעים אפשריים | פיצול ל"זהויות" לפי עוגנים משותפים (מייל / טלפון / ארגון / דומיין לא-ציבורי); הופעות ללא הקשר מזהה מוצגות בנפרד; שמות דומים מוצגים אך **לא** מאוחדים |
| זמן אמת | `GET /api/subjects/<id>` ו־`/events?after=` ; ה־UI מתעדכן כל 4 שניות |

## API

`POST /api/search {"query": "...", "kind": "person|org|email|phone|domain", "hours": 6}` · `GET /api/subjects/<id>` · `GET /api/subjects/<id>/events?after=N` · `POST /api/subjects/<id>/stop` · `GET /api/entities?q=` · `GET /api/stats`.
ברירת מחדל: `127.0.0.1`. חשיפה החוצה → הגדירו `OSNIT_TOKEN` (Bearer). POST דורש `application/json` ו־same-origin.

## מגבלות ידועות (כנות)

- חילוץ שמות הוא **precision-first**: אדם מזוהה כשהוא הנושא המבוקש, עם תואר (כולל "וד\"ר"), צמוד לתפקיד, בשורת "שם:/התובע:", או כשם פרטי מוכר + שם משפחה (מילון; שמות דו־משמעיים כמו "גל"/"טל" רק אם השם המלא חוזר). אין NER סטטיסטי.
- איכות נמדדת על קורפוס מתויג (`tests/corpus*`). על סט מבחן שלא שימש לכוונון הראשוני: precision 100%, recall 45% → אחרי תיקונים כלליים 100%/100%, recall קשרים 83%. הקורפוס קטן (11 מסמכים) — הכי טוב להוסיף דפים אמיתיים שלכם: `<שם>.html` + `<שם>.gold.json` ולהריץ `osnit eval`.
- בדף ספריה/אלפון (12+ אנשי קשר) נשמרות רק שורות של נושא מבוקש; דף צוות גדול מאוד (30 כרטיסים) עלול להיחשב אלפון ולאבד שיוכים שאינם באותה שורה.
- אין הכרעה בין שני אנשים בעלי אותו שם ללא עוגן משותף; במקרה כזה הם יופיעו בשתי זהויות או כ"לא משויך" — זו המלצה לבדיקה אנושית, לא קביעה.
- איחוד בין־לשוני של ארגון בעל שם קצר מאוד (למשל "אלפא"/"Alpha") נעשה רק כשיש דומיין משותף שמאשש אותו.
- אין JavaScript rendering, ואין התחברות/מקורות מאחורי login (בכוונה).
- מילון התעתיק קטן; כדאי להרחיב ב־`data/name_variants.json` (`{"חייט": ["hayat", ...]}`).
- SQLite מספיק לעשרות/מאות אלפי דפים; מעבר לכך — להחליף את `store.py` ב־Postgres.

## אחריות ופרטיות

המערכת אוספת רק מידע שפורסם בפומבי, ומכבדת robots.txt, אך **צבירה של מידע על אדם פרטי** עשויה להיות מוסדרת (חוק הגנת הפרטיות הישראלי ותקנותיו, GDPR). השתמשו בה למטרה לגיטימית ומוגדרת (מחקר, אבטחה, בדיקת נאותות), הגבילו גישה ל־DB, ותנו מענה לבקשות הסרה/מחיקה (`python -m osnit forget "<שם/מייל/טלפון>"` מוחק ישות עם כל הראיות והקשרים שלה). הערכות הביטחון הן הסתברותיות — לא לקבל החלטות על אדם על סמך התוצאה בלבד.
