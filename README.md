# osnit-il — מנוע OSINT ציבורי מתמשך

מנוע שמתחיל ממאגר קיים, ממשיך לגלות מידע חדש מ**מקורות ציבוריים** באופן אוטונומי, ומרכז הכול לתמונה אחת שמתעדכנת — עם הוכחות ורמת ביטחון לכל נתון. (Python 3.10+, ללא תלויות חובה; `pypdf` אופציונלי ל־PDF.)

```
חיפוש → תוצאה ראשונית מיידית (מהמאגר) → גילוי מקורות → סריקה → פרסור → קורלציה → עדכון התמונה → סבב נוסף
```

## הפעלה מהירה — אתר מקומי

**Windows:** לחיצה כפולה על `run.bat` (דורש Python 3.10+ מ־python.org). נפתח דפדפן על http://localhost:8080.
**Linux/Mac/NAS:** `./run.sh`

מפתחות חיפוש והגדרות: בהרצה הראשונה נוצר קובץ `osnit.env` ליד `run.bat` — ממלאים בו מפתח (Google/SerpAPI/Brave/SearXNG) ומפעילים מחדש.

באתר:
- **לוח מחוונים**: סטטיסטיקות — כמה אנשים/מיילים/טלפונים/ארגונים/מסמכים, כמה "זהויות מלאות" (שם + ארגון/תפקיד + מייל או טלפון ציבורי), גרף פעילות 30 יום, ארגונים ודומיינים מובילים, איכות המידע וממצאים אחרונים. עיצוב כהה/מודיעיני (יש מתג תצוגה).
- **קבצים**: גרירת קובץ או רשימת קבצים (SQL/SQLite/CSV/TSV/XLSX/XLS/JSON/JSONL/XML/PDF/DOCX/HTML/TXT/VCF). כל קובץ עובר קודם **ניתוח** (ראו למטה) ומיד מוצג מה נמצא בו — סוגי המידע, זיהוי כל עמודה, דוגמת רשומות, ומה כבר מוכר במאגר. אפשר לעצור אחרי הניתוח, לתקן עמודות ולאשר; למחוק את כל המידע שנכנס מקובץ מסוים; ולייבא מחדש עם תיקונים. אפשר גם להעתיק קבצים לתיקיית `data/inbox`.
- **סוגי מידע**: הוספת סוג מידע משלכם (למשל "מספר עובד") — שם, שמות עמודה, דוגמאות לערכים (התבנית נלמדת מהן) או regex, והאם הוא מזהה שמקשר בין קבצים; רשימת שמות העמודות שהמערכת למדה; השדות שנשמרו מקבצים.
- **מאגר**: כמה מקורות/ישויות/קשרים יש, חיפוש בכל מה שכבר נאסף, מקורות אחרונים.
- **כרטיס ישות**: כל מה שידוע על אדם/מייל/טלפון/ארגון — כתיבים, קשרים, ואיפה נראה; כפתור "חיפוש עמוק ברשת".
- **חיפוש עמוק**: תשובה ישירה לבקשה, זהויות אפשריות, גרף קשרים, סינון לפי ביטחון, ייצוא CSV/JSON, ועדכון חי בזמן שהסריקה רצה (‎`?nolive` לרענון תקופתי במקום).
- בצד: כל החיפושים שהרצתם וכמה ממצאים יש בכל אחד.

### ניתוח קבצים בעומק

```
קובץ → 1. ניתוח (קריאה בלבד) → [אישור / תיקון עמודות] → 2. ייבוא → קישור למה שכבר במאגר
```

1. **מציאת רשומות** — לא רק בטבלאות: גם בתוך PDF / Word / טקסט / HTML — בלוקים של `שדה: ערך` (גם vCard), שורות עם מפריד (`|` `;` טאב) עם או בלי שורת כותרת, שורות "חופשיות" שמפוצלות לפי מה שכל חלק הוא (טלפון / מייל / תאריך / טקסט), טבלאות HTML, XML, ו־JSON מקונן בכל עומק (`address.city`).
2. **זיהוי כל עמודה** — לפי סדר אמינות: התיקון שלכם → מה שלימדתם → שם עמודה מוכר → **התוכן עצמו** → מה שנלמד מקבצים קודמים → חלק משם העמודה. כ־30 סוגים מובנים: שם / שם פרטי / משפחה, ארגון, תפקיד, מייל, טלפון, **כתובת** (עברית ואנגלית, גם מורכבת מרחוב+מספר+עיר), עיר, מיקוד, מדינה, קואורדינטות, אתר, **פרופיל ברשת** (LinkedIn/Facebook/…), **שם משתמש**, IP, תאריך / תאריך לידה, מגדר, גיל, סכום, קוד — ועוד הסוגים שלכם. עמודה `JJDBD` מלאה בכתובות → מזוהה ככתובת, ונזכרת כך לקבצים הבאים.
3. **מה קורה לכל עמודה** — 🔗 *מזהה* (שם, מייל, טלפון, כתובת, שם משתמש, פרופיל, אתר, **ת"ז**, מזהה משלכם) הופך לישות, כך שאותו ערך בשני קבצים מחבר בין הרשומות; 📎 *שדה* נשמר על האדם/הארגון **בשם העמודה המקורי** (עם שם מוצע בעברית כשאפשר, או "לא מזוהה"); ⚙ *טכני* (id וכו') — לא נשמר. **שום עמודה לא נזרקת אוטומטית** — זה המאגר שלכם: עמודות רגישות (סיסמה / גיבוב / אשראי / ת"ז) נשמרות תחת הסוג שלהן ומסומנות, ות"ז גם מקשרת רשומות. מי שלא רוצה עמודה מסוימת — מסמן לה "לא לשמור" ידנית (או מגדיר סוג כ"רגיש — לא לשמור").
4. **קישור בין קבצים** — כבר בשלב הניתוח: "2 ערכים מוכרים — yon@gmail.com שייך ל: יונתן חייט (customers.csv)". אחרי הייבוא: כמה ישויות מהקובץ מתחברות למקורות אחרים. בדף של מייל/טלפון/כתובת — כל מי שזה שייך לו מכל הקבצים, עם שאר הפרטים שלו; בדף של אדם — אנשים אחרים שחולקים איתו מזהה (המלצה לבדיקה, בלי איחוד אוטומטי).
5. **חיפוש** — כל ממצא מסומן 📁 מקובץ (ואיזה) או 🌐 מהרשת, עם סינון "הכול / מקבצים / מהרשת".
6. **תיק זהות (חוטים)** — מכל כרטיס אדם/ישות: "🧵 תיק זהות" אוסף את כל הרשומות באותו שם (בכל כתיב — עברית/אנגלית/שגיאות), מחבר אותן לאדם אחד לפי **מזהה אישי משותף** (מייל, שם משתמש, פרופיל, ת"ז, מזהה שלכם, טלפון שלא משותף לרבים), ומצייר גרף חוטים: האדם במרכז, הפרטים סביבו, וחוט מקווקו לכל אדם אחר שחולק פרט. כל פרט מדורג (מקורות בלתי־תלויים, כמה רשומות מאשרות, וכמה הוא בלעדי — טלפון שמשויך ל־3 אנשים נחשב עדות חלשה). שמות שונים שחולקים פרט מוצגים כחוטים — לא מאוחדים.
7. **מחיקה ואיפוס** — מחיקת כל המידע מקובץ אחד (מתוך רשימת הקבצים, עם מה שכל אחד הכניס); או לפי מקור: כל הקבצים / כל הרשת / איפוס מלא. מחיקה גורפת דורשת קוד איפוס (`OSNIT_RESET_CODE`, ברירת מחדל 1212). פרט שנמצא גם במקור אחר נשאר עם ההוכחות מהמקור האחר.

### שורת פקודה

```bash
pip install pypdf                      # אופציונלי: תמיכה ב-PDF
python -m osnit serve --seeds seeds/example_seeds.txt   # UI + API + סריקה 24/7 על http://127.0.0.1:8080
python -m osnit search "יונתן חייט" --wait 600          # חיפוש עמוק מהטרמינל, תמונה מעודכנת אחרי 10 דקות
python -m osnit import ./archive --base-url https://example.org/files   # קבצים היסטוריים / JSONL
python -m osnit import-db old_tool.sql --dry-run    # גם SQL dump, SQLite, CSV/TSV, JSON/JSONL         # אילו עמודות זוהו בכל טבלה
python -m osnit import-db old_tool.db --label old-tool --delete-raw   # ייבוא מסד מתוכנה קודמת ומחיקת הקובץ
python -m osnit search "יונתן חייט מספר טלפון"           # שאילתה חופשית: שם + כוונה (טלפון / מייל / pdf / קורות חיים)
python -m osnit analyze leads.pdf                        # שלב הניתוח בלבד: טבלאות, סוג כל עמודה, דוגמאות, חפיפה עם המאגר
python -m osnit add-type "מספר עובד" --headers "emp_no,מספר עובד" --examples EMP-10023,EMP-88123
python -m osnit reset files --yes                        # מחיקת כל המידע מקבצים (או web / all)
python -m osnit stats
python -m osnit forget "yonatan.hayat@alpha.co.il"   # בקשת הסרה
python -m unittest discover -s tests -t .               # בדיקות (ללא רשת)
python -m osnit eval tests/corpus_holdout               # מדידת איכות חילוץ על קורפוס מתויג
```

### מקורות גילוי (`--providers` / `OSNIT_PROVIDERS`)

| ספק | מה הוא נותן | הגדרה |
|---|---|---|
| `google` | חיפוש כמו בגוגל, כולל `"שם" filetype:pdf`, `site:` — דרך Google Programmable Search JSON API הרשמי | `GOOGLE_API_KEY` + `GOOGLE_CSE_ID` (מנוע שמוגדר לחפש בכל הרשת) |
| `serpapi` | תוצאות google.com דרך שירות API בתשלום | `SERPAPI_KEY` |
| `brave` | Brave Search API | `BRAVE_API_KEY` |
| `searxng` | מטא-חיפוש בהתקנה עצמית (מתאים ל-NAS) | `SEARXNG_URL` |
| `archive` | Wayback Machine: צילומים היסטוריים של אתרים שקשורים לנושא — מסמכים קודם (ברירת מחדל) | — |
| `wikipedia` | חיפוש בוויקיפדיה עברית+אנגלית — **opt-in בלבד** (`OSNIT_PROVIDERS=wikipedia`) | — |
| `ddg` | scraping של DuckDuckGo — opt-in בלבד | — |

ספק עם מפתח מופעל אוטומטית. לכל ספק בתשלום/מוגבל יש מכסה יומית (`OSNIT_BUDGET_GOOGLE=100` וכו'); משימות מעבר למכסה ממתינות ליום הבא.
גוגל עצמו לא נסרק ישירות (חוסם ואסור בתנאי השימוש) — רק דרך API.
כשאתר מזכיר את הנושא, נסרקים גם ה־sitemap שלו (מסמכים קודם) והצילומים ההיסטוריים שלו.

**החיפוש ממוקד ולא "כללי".** אתרים כלליים — ויקיפדיה, מקורות תורניים, מילונים, אתרי משמעות־שמות ומילות־שיר — **אינם נסרקים** (הם מלאים בשמות של דמויות היסטוריות/מקראיות ולא על האדם הפרטי). שאילתות של אדם מכוונות לְמְקומות שבהם אנשים אמיתיים מופיעים: פרופילים (LinkedIn/Facebook/…), אתרי `gov.il`/`ac.il`/`org.il`, אתרי חדשות ישראליים, ומסמכים (`filetype:pdf`). אפשר להרחיב את חסימת האתרים ב־`OSNIT_BLOCK_DOMAINS`. טקסט מקראי/פרשני שנקלט בכל זאת מזוהה, ושמות הדמויות שבו אינם נשמרים.

## מה בנוי

| יכולת | מימוש |
|---|---|
| סריקה רציפה | תור מקורות ב־SQLite, N workers, עדיפות (תוצאות חיפוש > קישורים מדף עם ממצא > crawl כללי), fairness לפי דומיין |
| נימוס | robots.txt (+Crawl-delay), השהיה לכל host, תקרת גודל/זמן, `Retry-After`, חסימת כתובות פנימיות (SSRF) גם בהפניות |
| פרסור | HTML (כולל JSON-LD, mailto/tel), PDF (כולל תיקון עברית הפוכה), DOCX, **Excel xlsx/xls**, CSV/TSV, JSON/JSONL, **SQL dump**, SQLite, TXT, VCF, XML/sitemap; קידודים windows-1255 / iso-8859-8. גיליונות Excel ו-SQL נקראים כשורות ועמודות עם מיפוי עמודות אוטומטי |
| חילוץ | שמות (התאמת נושא + תארים + צמידות תפקיד), ארגונים, תפקידים, מיילים (גם `[at]`/`[dot]`), טלפונים (נרמול ל־E.164), דומיינים, URLs, וקשרים ביניהם |
| נרמול/איחוד | ניקוד, אותיות סופיות, סדר שמות, גרשיים; תעתיק עברית↔לטינית (מילון + כללים, ניתן להרחבה ב־`data/name_variants.json`); איחוד שגיאות כתיב בטוח (עריכה ≤1, מילים ≥5 תווים) |
| איחוד בין שפות | ארגון/תפקיד/אדם בעברית ובאנגלית מאוחדים בתצוגה לפריט אחד (עם "גם: …"): שלד עיצורים + מילון שמות + דומיין משותף; מנכ"ל=CEO, יו"ר=Chairman וכו' |
| Evidence | לכל נתון וקשר: מקור, קישור, ציטוט, ביטחון, `first_seen` / `last_seen` |
| ביטחון | noisy-or על **דומיינים בלתי־תלויים** (עשר הופעות באותו אתר ≠ אישוש) |
| בלי עבודה חוזרת | hash של ה־raw ושל הטקסט, ETag / Last-Modified (304), מרווח סריקה שמוכפל כשאין שינוי |
| זיהוי שינויים | `source_changes` (כמה עובדות נוספו / נעלמו), ולכל ממצא סטטוס: **פעיל** / **נעלם מהמקור** / **היסטורי** (מיובא); התראת "נעלם" כשעובדה על הנושא ירדה מדף; ניסוח שהשתנה סביב אותה עובדה לא נחשב היעלמות |
| מה חדש מאז | `GET /api/subjects/<id>?since=<ts>` מסמן ממצאים חדשים ומסכם כמה נוספו/נעלמו; ה־UI זוכר מתי צפיתם לאחרונה בכל נושא |
| raw לא נשמר | ה־body נשאר בזיכרון בלבד ונזרק אחרי הפרסור; בסכמה אין עמודה לתוכן גולמי. בייבוא קבצים/מסדים: `--delete-raw` (או `OSNIT_DELETE_IMPORTED=1` כברירת מחדל) מוחק את הקובץ רק אחרי ייבוא מוצלח |
| וריאציות טלפון | חיפוש טלפון ישראלי בכל הכתיבים: 05X-XXX-XXXX, 05XXXXXXXX, +972-5X-…, 972…, רווחים/מקפים — כדי למצוא אותו איך שלא נכתב בדף/קובץ |
| הבנת שאילתה | "יונתן חייט pdf" / "נקודה PDF" / "filetype:docx" / "מספר טלפון" / "מייל" / "קורות חיים" → נושא + כוונה; החיפושים המבוקשים מתוכננים ראשונים, והתוצאה כוללת "תשובה לבקשה" |
| שער סבירות | דף ספריה (הרבה טלפונים) → רק שיוך באותה שורה, ביטחון ≤50%; דף ספאם → לא נשלף ממנו כלום; מספר מרכזייה שמשויך ל־3+ אנשים → לא אישי; `info@`/`office@` → שיוך חלש; מספרים רצופים/חוזרים ו־`example.com` → נדחים |
| דשבורד | סטטיסטיקות לכל סוג, "זהויות מלאות" (שם+ארגון/תפקיד+מייל/טלפון ציבורי — **ללא סיסמאות/קרדנציאלס**), פעילות 30 יום, טופ ארגונים/דומיינים, איכות מידע |
| העלאת קבצים | גרירה לאתר או תיקיית inbox, תור עם אחוז התקדמות לכל קובץ, זיהוי מבנה אוטומטי (כולל SQL dump), מחיקת הקובץ הגולמי אחרי עיבוד |
| ייבוא מסד קיים | `import-db`: SQLite / CSV / TSV / JSON / JSONL, זיהוי עמודות בעברית/אנגלית או קובץ מיפוי, תאריך הגילוי ההיסטורי נשמר לכל רשומה, עמודות טקסט/HTML עוברות חילוץ מלא, כתובת המקור נכנסת לתור לאימות מחדש |
| חיפוש עמוק | וריאציות שם → תוצאה מיידית מהמאגר (כולל איחוד עם אזכורים קודמים) → משימות גילוי → סבבי הרחבה אוטומטיים (ארגון, מייל, דומיין שנמצאו) עד `--hours` |
| מופעים אפשריים | פיצול ל"זהויות" לפי עוגנים משותפים (מייל / טלפון / ארגון / דומיין לא-ציבורי); הופעות ללא הקשר מזהה מוצגות בנפרד; שמות דומים מוצגים אך **לא** מאוחדים |
| תיק זהות + גרף חוטים | כל הרשומות בשם אחד (בכל כתיב) → אשכולות לפי מזהה אישי משותף → גרף כוח (force-directed) של האדם, פרטיו, וחוטים לאנשים אחרים שחולקים פרט; דירוג בלעדיות לכל פרט |
| סוגי מידע | ~30 סוגים מובנים + סוגים שהמשתמש מגדיר (תבנית נלמדת מדוגמאות/regex); שום עמודה לא נזרקת אוטומטית — עמודות רגישות נשמרות ומסומנות, ת"ז מקשרת רשומות |
| זמן אמת | `GET /api/subjects/<id>` ו־`/events?after=` ; ה־UI מתעדכן כל 4 שניות |

## API

ניתוח וקבצים: `GET /api/imports/<id>` (ניתוח + סיכום) · `POST /api/imports/<id>/approve {"overrides": {"<table>": {"<column>": "<type>|skip"}}, "teach": true}` · `POST /api/imports/<id>/reanalyze` · `POST /api/imports/<id>/purge` · `POST /api/upload?review=1` · `POST /api/reset {"scope": "files|web|all", "confirm": "<קוד איפוס>"}` · `GET/POST /api/types` (`{"label", "headers", "examples" | "pattern", "identifier", "sensitive"}`) · `GET/POST /api/fields` · `GET /api/dossier?name=<שם>` או `?eid=<id>` (תיק זהות + גרף חוטים).

`POST /api/search {"query": "...", "kind": "person|org|email|phone|domain", "hours": 6}` · `GET /api/subjects/<id>` · `GET /api/subjects/<id>/events?after=N` · `POST /api/subjects/<id>/stop` · `GET /api/entities?q=` · `GET /api/stats`.
ברירת מחדל: `127.0.0.1`. חשיפה החוצה → הגדירו `OSNIT_TOKEN` (Bearer). POST דורש `application/json` ו־same-origin.

## מגבלות ידועות (כנות)

- חילוץ שמות הוא **precision-first**: אדם מזוהה כשהוא הנושא המבוקש, עם תואר (כולל "וד\"ר"), צמוד לתפקיד, בשורת "שם:/התובע:", או כשם פרטי מוכר + שם משפחה (מילון; שמות דו־משמעיים כמו "גל"/"טל" רק אם השם המלא חוזר). אין NER סטטיסטי.
- איכות נמדדת על קורפוס מתויג (`tests/corpus*`). על סט מבחן שלא שימש לכוונון הראשוני: precision 100%, recall 45% → אחרי תיקונים כלליים 100%/100%, recall קשרים 100% (כולל תפקיד במשפט זיקה: "Eran Dahan, who will remain Chairman" / "נועה פרץ, שתמשיך לכהן כיו"ר"). הקורפוס קטן (11 מסמכים) — הכי טוב להוסיף דפים אמיתיים שלכם: `<שם>.html` + `<שם>.gold.json` ולהריץ `osnit eval`.
- זיהוי עמודה לפי תוכן נעשה על דגימה של 300 השורות הראשונות; עמודה שמתחילה ריקה ומתמלאת רק בהמשך תזוהה לפי שמה בלבד. אפשר תמיד לתקן במסך הניתוח.
- כתובת בעברית מזוהה כשיש מילת רחוב (רח'/שד'/דרך…) או עיר מוכרת אחרי המספר — “קומה 3” או “מנכ"ל 2” לא ייחשבו כתובת. רשימת הערים מכסה את רוב היישובים הגדולים.
- אותו אדם שנכתב פעם בעברית ופעם באנגלית בשני קבצים (יונתן חייט / Yonatan Hayat) מוצג כ"מחובר דרך פרטים משותפים", לא מאוחד אוטומטית.
- Excel ישן (.xls, פורמט BIFF) נקרא רק אם מותקן `xlrd`; אחרת שומרים כ-xlsx או CSV. .xlsx עובד תמיד.
- החיפוש ברשת ממוקד: כשקוראים דף נשמר רק הנושא שחיפשת ומה שמקושר אליו, ולא עוקבים אחרי קישורי דפים — רק מורידים קבצים (PDF/DOCX/XLSX) שמופיעים בו. הרשת נסרקת רק כשמפעילים חיפוש, ויש כפתור עצירה.
- בדף ספריה/אלפון (12+ אנשי קשר) נשמרות רק שורות של נושא מבוקש; דף צוות גדול מאוד (30 כרטיסים) עלול להיחשב אלפון ולאבד שיוכים שאינם באותה שורה.
- אין הכרעה בין שני אנשים בעלי אותו שם ללא עוגן משותף; במקרה כזה הם יופיעו בשתי זהויות או כ"לא משויך" — זו המלצה לבדיקה אנושית, לא קביעה.
- איחוד בין־לשוני של ארגון בעל שם קצר מאוד (למשל "אלפא"/"Alpha") נעשה רק כשיש דומיין משותף שמאשש אותו.
- אין JavaScript rendering, ואין התחברות/מקורות מאחורי login (בכוונה).
- מילון התעתיק קטן; כדאי להרחיב ב־`data/name_variants.json` (`{"חייט": ["hayat", ...]}`).
- SQLite מספיק לעשרות/מאות אלפי דפים; מעבר לכך — להחליף את `store.py` ב־Postgres.

## אחריות ופרטיות

המערכת אוספת רק מידע שפורסם בפומבי, ומכבדת robots.txt, אך **צבירה של מידע על אדם פרטי** עשויה להיות מוסדרת (חוק הגנת הפרטיות הישראלי ותקנותיו, GDPR). השתמשו בה למטרה לגיטימית ומוגדרת (מחקר, אבטחה, בדיקת נאותות), הגבילו גישה ל־DB, ותנו מענה לבקשות הסרה/מחיקה (`python -m osnit forget "<שם/מייל/טלפון>"` מוחק ישות עם כל הראיות והקשרים שלה). הערכות הביטחון הן הסתברותיות — לא לקבל החלטות על אדם על סמך התוצאה בלבד.
